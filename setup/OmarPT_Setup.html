📖 Overview

This guide will help you clone the Taupiri Sound project and set it up as a fresh project for OmarPT. The process ensures:

  • Preserves destination branch git history - Your existing commits stay intact
  • No source git history transferred - Only the latest files from source, not the commit history
  • Complete file replacement - All files (including hidden config files) replaced from source
  • Latest package versions - Instead of using locked versions from source
  • New Sanity.io setup - Fresh Sanity project for OmarPT
  • New Resend setup - Fresh email service for OmarPT

1Clone Source Branch and Replace Destination Files

IMPORTANT: This process clones the source branch WITHOUT git history, then replaces all files in your destination branch while PRESERVING the destination's git history.

Step 1a: Clone the source branch and replace destination files

# Navigate to your destination project directory (the one with existing files)
cd /path/to/your/destination-project

# Make sure you're on the correct destination branch
git checkout your-destination-branch

# OPTIONAL BUT RECOMMENDED: Create a backup branch before proceeding
git branch backup-before-template-$(date +%Y%m%d)

# Clone the specific source branch (replace 'development' with your desired branch)
# This command clones only the latest commit without history
git clone --depth 1 --branch development https://github.com/yourusername/taupiri-website.git temp-clone

# Remove ALL existing files in destination (INCLUDING hidden files, but NOT .git)
# This ensures a complete replacement
find . -mindepth 1 -maxdepth 1 ! -name '.git' -exec rm -rf {} +

# Move all files from the temp clone to the current directory
mv temp-clone/* ./
mv temp-clone/.??* ./ 2>/dev/null || true  # Move hidden files (but not . or ..)

# Clean up temporary clone directory
rm -rf temp-clone
Why delete hidden files? Hidden files like .env.local, .gitignore, .eslintrc, etc. from the destination project need to be replaced with the source project's versions to ensure configuration consistency. The only file we preserve is .git (the git history).
What this does:
  • ✅ Preserves your destination branch's git history
  • ✅ Replaces ALL files (visible and hidden) with source files
  • ✅ No git history from source project is transferred
  • ✅ You can commit the changes to your existing branch

Step 1b: Commit the replaced files to your destination branch

# Check what files were changed
git status

# Add all the new/changed files
git add .

# Commit the template files to your destination branch
git commit -m "Replace all files with Taupiri Sound template

- Complete file replacement from Taupiri Sound project
- Preserves destination branch git history
- Ready for customization to OmarPT project"

# Push to your destination repository
# No force push needed - we're just adding a new commit to existing history
git push origin your-destination-branch
Result: Your destination branch now has all files from Taupiri Sound as a new commit in your existing git history. If something goes wrong, you can easily revert this commit or switch to your backup branch.

2Update Dependencies to Latest Versions

IMPORTANT: Install latest versions of all dependencies instead of using locked versions from Taupiri Sound.

Delete existing dependency lock files:

rm package-lock.json

Update package.json with latest dependency versions:

# This command updates all dependencies to their latest versions
npx npm-check-updates -u

Install the updated dependencies:

npm install

Test that everything works:

npm run build
npm run typecheck
Note: If there are breaking changes from version updates, you may need to address them. Check the build output for errors and review dependency changelogs.

4Environment Variables Setup

CRITICAL: You MUST update all environment variables with your new Sanity and Resend credentials.

A. Create New Sanity Project

  1. Go to sanity.io/manage
  2. Click "Create new project"
  3. Name your project (e.g., "OmarPT Website")
  4. Create a dataset (e.g., "production" and/or "development")
  5. Copy your Project ID (you'll need this for .env.local)
  6. Go to API settings and create a Read Token with Viewer permissions
  7. Optionally create a Write Token if needed

B. Create New Resend Account/Project

  1. Go to resend.com and sign up or log in
  2. Create a new API key
  3. Copy the API key (you'll need this for .env.local)
  4. For production: Add and verify your domain
  5. For development: You can use onboarding@resend.dev as the from address

C. Update .env.local File

File: .env.local

Replace ALL values with your new project details:

# Environment
NEXT_PUBLIC_ENV="development"

# Sanity Configuration - UPDATE WITH YOUR NEW PROJECT
NEXT_PUBLIC_SANITY_PROJECT_ID="your-new-sanity-project-id"
NEXT_PUBLIC_SANITY_DATASET="development"  # or "production"
NEXT_PUBLIC_SANITY_STUDIO_URL="/studio"

# Site Configuration
NEXT_PUBLIC_BASE_URL="http://localhost:3000"  # For development

# Sanity API Tokens - GET THESE FROM YOUR NEW SANITY PROJECT
SANITY_API_READ_TOKEN="your-new-sanity-read-token"

# Resend API Configuration - GET THIS FROM YOUR NEW RESEND ACCOUNT
RESEND_API_KEY="your-new-resend-api-key"

# Email Configuration
NEXT_PUBLIC_CONTACT_EMAIL="contact@omarpt.com"  # Where form submissions go
RESEND_FROM_EMAIL="OmarPT "  # For dev; use verified domain for prod

# THIS ONE NOT NEEDED ON VERCEL
SANITY_API_WRITE_TOKEN="your-new-sanity-write-token"  # Optional
Production Environment Variables: When deploying to Vercel, you'll need to add all these variables (except SANITY_API_WRITE_TOKEN) to your Vercel project settings under "Environment Variables".

6Brand Colors and Styling

CRITICAL CSS DUPLICATION: Brand colors must be updated in TWO locations for performance optimization.

A. Update Brand Colors in Globals CSS

File: src/app/globals.css

Update the brand color values (around line 16-28):

@theme {
  --color-brand-primary: #YOUR_PRIMARY_COLOR;     /* Change from #900000 */
  --color-brand-secondary: #YOUR_SECONDARY_COLOR; /* Change from #430c08 */
  --color-body: #YOUR_BODY_COLOR;                 /* Change from #71221d */
  --color-subtle: #YOUR_SUBTLE_COLOR;             /* Change from #b8956a */
  --color-brand-black: #YOUR_DARK_COLOR;          /* Change from #0a0000 */
  --color-brand-white: #YOUR_LIGHT_COLOR;         /* Change from #fffbe8 */
  --color-brand-white-dark: #YOUR_LIGHT_DARK;     /* Change from #fcf3d7 */

  /* Update gradient backgrounds to use your new colors */
  --background-image-brand-gradient-brown: linear-gradient(135deg, #YOUR_SECONDARY_COLOR 0%, #YOUR_DARK_COLOR 100%);
  --background-image-brand-gradient-red: linear-gradient(135deg, #YOUR_PRIMARY_COLOR 0%, #YOUR_SECONDARY_COLOR 100%);
  --background-image-brand-gradient-subtle: linear-gradient(135deg, #YOUR_PRIMARY_COLOR 0%, #YOUR_MEDIUM_COLOR 100%);
  --background-image-brand-gradient-text: linear-gradient(to right, #YOUR_PRIMARY_COLOR 0%, #YOUR_SECONDARY_COLOR 100%);
}

B. Update Critical CSS in Layout

File: src/app/layout.tsx

Update the inline critical CSS (around line 78-81):

/* Essential brand colors for immediate render */
:root {
  --color-brand-primary: #YOUR_PRIMARY_COLOR;     /* Must match globals.css */
  --color-brand-secondary: #YOUR_SECONDARY_COLOR; /* Must match globals.css */
}
Why update both? The inline styles in layout.tsx load immediately for faster page rendering, while globals.css contains the complete styling. They must match to prevent visual flashing.

The PWA manifest colors in src/lib/constants.ts should match your brand colors (already updated in Step 5).

🛠 Troubleshooting

Common Issues:

  • Sanity Studio not loading: Check NEXT_PUBLIC_SANITY_PROJECT_ID and SANITY_API_READ_TOKEN in .env.local
  • Build errors after dependency updates: Review breaking changes in package changelogs, may need to downgrade specific packages
  • Type errors: Run npm run typegen to regenerate Sanity types
  • Email not sending: Verify RESEND_API_KEY is correct and from address is valid
  • Wrong domain in robots.txt: Check PRODUCTION_DOMAIN in src/lib/constants.ts
  • Colors not updating: Clear browser cache and ensure both globals.css AND layout.tsx are updated

Getting Help:

  • Check Sanity project settings at sanity.io/manage
  • Verify Resend API key at resend.com
  • Review browser console for JavaScript errors
  • Check server logs for API errors
